# 🥘 Огузок
 
> Я всегда знал, что буду поваром... Не милиционером, не пожарным, не космонавтом, даже не президентом, а именно поваром...
 
Telegram-бот для тех, у кого в холодильнике яйца, сыр и полпачки макарон, а из техники микроволновка и одна сковородка на этаж.
 
Пишешь ему, что у тебя есть, он находит, что из этого приготовить. Характер у него, правда, так себе.
 
**Попробовать: [@oguzokcooking_bot](https://t.me/oguzokcooking_bot)**

## Что умеет
 
**🔍 По продуктам.** Пишешь через запятую, что есть дома: `яйца, сыр, молоко`. Огузок проверяет каждый рецепт, считает совпадения и показывает три самых подходящих с пометкой «совпало 2 из 3».
 
**💪 ПП.** Низкокалорийное и белковое. У каждого рецепта КБЖУ на порцию, так что считать самой ничего не надо.
 
**⚡ Быстрое.** Когда есть хочется прямо сейчас.
 
**🎲 Рандом.** Когда вообще без идей.
 
В каждом рецепте есть время, техника (микроволновка, сковородка, кастрюля или вообще без готовки), продукты и пошаговый способ приготовления.
 
И да, на стикеры и фотки он тоже отвечает. Не очень вежливо:
 
```
ты:      [стикер]
огузок:  Нах мне твои стикеры чувак. Иди готовь.
 
ты:      [фото]
огузок:  Маме такое отправляй.
```
 
## Как это устроено
 
```
Пользователь ──▶ Telegram ──webhook──▶ Flask (PythonAnywhere) ──▶ aiogram
                                                                     │
                                          recipes.json ──▶ Recipe ◀──┘
```
 
Бот не крутится постоянно и не спрашивает Telegram каждую секунду, есть ли новые сообщения. Telegram сам присылает каждое сообщение на Flask-приложение, а оно передаёт его в диспетчер aiogram. Так бот работает 24/7 на бесплатном тарифе PythonAnywhere.
 
Рецепты лежат в `recipes.json`. При запуске каждый превращается в объект класса `Recipe`, который сам умеет считать совпадения с продуктами пользователя и собирать себя в красивое сообщение.
 
Поиск по продуктам работает через FSM aiogram: после нажатия кнопки бот запоминает, что ждёт от этого человека список продуктов, и следующее сообщение обрабатывает уже как поиск.
 
## Стек
 
| | |
|---|---|
| Язык | Python 3.12 |
| Бот | aiogram 3 (FSM, фильтры, reply-клавиатуры) |
| Сервер | Flask, webhook с проверкой секретного токена |
| Данные | JSON |
| Хостинг | PythonAnywhere, исходящие запросы через aiohttp-socks |
 
## Структура
 
```
Oguzok-Cooking-Bot/
├── bot.py            # бот, обработчики, локальный запуск через polling
├── models.py         # класс Recipe и загрузка рецептов
├── keyboards.py      # кнопки меню
├── recipes.json      # база рецептов
├── flask_app.py      # приём вебхуков на сервере
├── set_webhook.py    # одноразовая установка вебхука
└── requirements.txt
```
 
## Запуск у себя
 
```bash
git clone https://github.com/ТВОЙ_НИК/Oguzok-Cooking-Bot.git
cd Oguzok-Cooking-Bot
python -m venv venv
```
 
Активировать окружение: на Windows `venv\Scripts\activate`, на Linux и Mac `source venv/bin/activate`.
 
```bash
pip install -r requirements.txt
```
 
Создай `.env` в корне проекта:
 
```env
BOT_TOKEN=токен_от_BotFather
```
 
И запускай:
 
```bash
python bot.py
```
 
Локально бот работает через polling, Flask и вебхук для этого не нужны. Для тестов лучше завести отдельного бота в @BotFather: пока у боевого стоит вебхук, polling с его токеном работать не будет.
 
## Деплой на PythonAnywhere
 
На сервере в `.env` добавляются ещё две переменные:
 
```env
BOT_TOKEN=токен_боевого_бота
WEBHOOK_SECRET=длинная_случайная_строка
PROXY=http://proxy.server:3128
```
 
1. Клонируешь репозиторий в Bash-консоли, создаёшь venv, ставишь зависимости
2. Создаёшь веб-приложение с ручной настройкой, указываешь путь к venv
3. В WSGI-файле добавляешь папку проекта в `sys.path` и импортируешь `app` из `flask_app` как `application`
4. Reload
5. Локально запускаешь `python set_webhook.py` с тем же `WEBHOOK_SECRET`, чтобы Telegram знал, куда слать сообщения
Обновление: `git push` дома, `git pull` на сервере, Reload.
